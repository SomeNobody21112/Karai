# VALIDATION — how we know it works, with no labels

**Regenerate:** `mplads validate` (~35 seconds). Every number below comes from
`data/artifacts/validation.json`.

---

## The problem

There are **no fraud labels in any public MPLADS source**. So there is no test set, no
ground truth, and no honest way to report a fraud-detection accuracy. Any system claiming
one on this data has fabricated it.

That does not mean nothing can be validated. It means we have to be precise about **what**
we are validating.

## What we validate instead: the machinery

We take the real portfolio, deliberately plant anomalies of known type into ordinary works,
re-run the scoring pipeline, and ask: **did the system find what we planted?**

Four perturbation types, 250 works each, planted only into works that were **not already
surfaced** — so a hit is attributable to the injection, not to something the work already
had:

| Perturbation | What we do to the record | Which engine should catch it |
|---|---|---|
| `inflated_amount` | Multiply the recommended amount by 8–25× | Peer comparison |
| `stalled_lifecycle` | Back-date the recommendation by 900–2,200 days | Early warning / survival |
| `cloned_description` | Copy a sibling's description, agency and amount | Duplicate detector |
| `lifecycle_break` | Record completion with no sanction; back-date half | Compliance engine |

## Results

### Detection — did the corroboration rule surface it at all?

This is the measure of whether the technique works.

| Perturbation | Planted | **Detected** |
|---|---:|---:|
| `stalled_lifecycle` | 154 | **96.1%** |
| `inflated_amount` | 250 | **83.2%** |
| `lifecycle_break` | 250 | **58.0%** |
| `cloned_description` | 250 | **50.0%** |
| **Overall** | **904** | **69.2%** |

### Ranking — did it reach the top of the queue?

A separate question, and a lower number, **by design**. Audit-ROI multiplies priority by
rupee exposure, so a planted anomaly inside a ₹3 lakh work correctly ranks below a genuine
₹6 crore one. Recall@5000 by priority: `stalled_lifecycle` 46.8%, `lifecycle_break` 37.6%,
`inflated_amount` 26.8%, `cloned_description` 12.0%.

**A low recall@k with a high detection rate is the system behaving correctly, not failing.**
It found the anomaly and then ranked it beneath bigger money — which is what an
audit-prioritisation tool is supposed to do.

## Why two of the four are weaker

Reported rather than hidden:

- **`cloned_description` at 50%** — the duplicate signal fires only when the pair is
  near-identical **and** from the same agency **and** for a near-identical amount. Our
  injector copies all three, but the clone is only detected if the donor sits in the same
  `(state × archetype)` block. Cross-block clones are missed. Widening the blocks would
  raise this number and cost quadratically more compute.
- **`lifecycle_break` at 58%** — a lifecycle break is one signal family. Under the
  corroboration rule a work needs **two** independent families to surface, so a planted
  break in an otherwise unremarkable work correctly stays below the bar. Raising this would
  mean weakening corroboration, which would cost far more in false positives than it gains.

Both are honest consequences of design choices we would defend, not bugs.

## What this number is NOT

> **Recall on planted anomalies is not a real-world fraud detection rate.**

- A real irregularity need not produce any of these four patterns.
- The overwhelming majority of works that *do* produce them are perfectly legitimate — 194
  works at exactly ₹6.25 lakh in one peer group is a bulk street-light order, not a scheme.
- We validate that the technique detects the patterns it was designed to detect. Nothing
  more is claimed.

## Limitations of this harness

1. Perturbations are synthetic and generated by us — they cannot represent an adversary who
   knows the detector.
2. Injection happens post-pipeline on scored works, so the archetype assignment and Cox
   model are not refit around the perturbed rows.
3. Only four anomaly shapes are tested; the system carries seven signals.
4. `n=250` per type gives a ±3% band on each detection rate.
